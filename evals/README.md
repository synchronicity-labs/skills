# Evals

A [`claude plugin eval`](https://code.claude.com/docs/en/plugin-evals) suite. Each case starts a fresh, isolated Claude Code session with only this plugin loaded, sends a realistic prompt, and grades what happened. The sync. MCP server is mocked, so evals never touch a real account or start paid work.

## Layout

- `triggers/`: routing cases. Each prompt should load one specific skill, or, for the `neg-*` cases, no sync. skill. Most also check that nothing paid starts before the user approves a quote.
- `behavior/`: workflow cases with approval given in the prompt. Graders check tool order, the inputs sent to the mocked tools (asset IDs, idempotency keys, models, word IDs), the files written, and the final reply.
- `mocks/sync/`: one file per mocked tool, plus `_tools.json`, which is the hosted server's real tool list with its descriptions and input schemas. A tool without a mock file isn't available in the run. A case's own `mocks/sync/` adds to these, so `jobs_create-many` and `jobs_get-many`, mocked only in `behavior/batch-mcp-jobs-many`, are listed in that case alone.

## Edit

The cases in `triggers/` and `behavior/`, and some mocks, are generated by `python3 scripts/build_evals.py`. Edit that script rather than the generated files, then rerun it. The other files in `mocks/sync/` are written by hand.

## Run

```bash
# Everything, two runs per case, at most 6 runs at once
claude plugin eval . --runs 2 -j 6 --ablation none --scaffold --trust-plugin \
  --allow-tools Bash Write Edit

# One skill's cases
claude plugin eval . --tag lipsync --runs 3 --ablation none --scaffold --trust-plugin --allow-tools Bash Write Edit
```

- `--scaffold` creates the fixture files that some behavior cases need.
- `Bash` lets the upload case run its `curl PUT`. The sandbox blocks the network, so that case checks the request it builds and that nothing paid starts after the upload fails.
- `--ablation none` skips the no-plugin baseline. Without the plugin there are no sync. tools at all, so the baseline would score close to zero and tell you little.

Results land in `evals/results/<timestamp>/` (ignored by git), with an HTML report.

## Refresh the tool list

When the MCP server changes, rebuild `mocks/sync/_tools.json` from a build of `synchronicity-labs/mcp-server`, using the `tools/list` response as a non-ChatGPT client sees it and filtered to `HOSTED_HTTP_TOOL_ALLOWLIST` in `src/server.ts`. Then run `python3 scripts/validate.py`, which flags any tool name that a skill mentions but the server no longer has.
